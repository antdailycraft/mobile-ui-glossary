## 정의

Dialog는 현재 화면 위 가운데에 떠오르는 **모달** 창입니다. 뒤쪽 화면은 스크림으로 덮여 조작할 수 없고, 사용자가 다이얼로그의 버튼 중 하나를 고르거나 닫아야 원래 작업으로 돌아갑니다.

보통 제목, 짧은 설명, 그리고 오른쪽 아래의 버튼 한두 개로 구성됩니다. 사용자의 흐름을 끊기 때문에 정말 중요한 순간에만 써야 합니다. 국내에서는 흔히 "팝업"이라고 부릅니다.

## 사용하면 좋은 경우

- 삭제, 결제, 로그아웃처럼 **되돌릴 수 없거나** 영향이 큰 작업을 실행하기 전에 확인받을 때
- 권한 요청처럼 사용자가 **지금 결정해야** 다음으로 넘어갈 수 있을 때
- 네트워크 끊김처럼 작업을 계속할 수 없게 만드는 중요한 오류를 알릴 때

## 사용하지 말아야 할 경우

- "저장했습니다" 같은 **단순한 결과 알림**일 때. 흐름을 끊지 않는 Snackbar나 Toast를 씁니다.
- 되돌릴 수 있는 작업을 매번 확인받을 때. 바로 실행하고 Snackbar로 실행 취소를 제공하는 편이 낫습니다.
- 입력 항목이 많은 양식일 때. 모바일에서는 전체 화면 다이얼로그나 새 화면이 더 적합합니다.
- 다이얼로그에서 또 다른 다이얼로그를 띄울 때

## 플랫폼별 차이

| 항목 | Material Design 3 | iOS HIG |
|---|---|---|
| 공식 명칭 | Dialog (basic, full-screen) | Alert |
| 버튼 배치 | 오른쪽 아래, 텍스트 버튼 가로 정렬 | 버튼 2개는 가로, 3개 이상은 세로로 쌓음 |
| 바깥 탭 | 기본 다이얼로그는 스크림을 누르면 닫힘 | 바깥을 눌러도 닫히지 않음 |
| 파괴적 동작 | 버튼 문구로 결과를 분명히 표현 | `destructive` 스타일(빨간색 버튼) |
| 취소 버튼 | 왼쪽(확인 버튼 앞) | `cancel` 역할 버튼. 2개일 때 왼쪽 |

이 데모는 두 가지 다이얼로그를 비교합니다. 결정이 필요 없는 기본 다이얼로그는 스크림을 누르면 닫히지만, 되돌릴 수 없는 작업의 확인 다이얼로그는 스크림을 눌러도 닫히지 않습니다. 사용자가 **명시적으로** 고르게 하기 위해서입니다.

**접근성:** 열릴 때 다이얼로그 안으로 포커스를 옮기고, 열려 있는 동안 포커스가 밖으로 나가지 않게 가두며, 닫히면 다이얼로그를 연 버튼으로 포커스를 돌려줍니다. 파괴적 확인에서는 실수를 막기 위해 "취소"에 먼저 포커스를 둡니다.
