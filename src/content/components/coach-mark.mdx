## 정의

Coach Mark는 처음 보는 기능이나 바뀐 화면을 **한 단계씩** 짚어 주는 안내입니다. 설명할 요소 주변만 구멍처럼 밝게 남기고 나머지 화면은 스크림으로 덮습니다. 그 옆에 말풍선을 띄워 "이 버튼으로 무엇을 할 수 있는지" 알려 줍니다.

보통 "다음"과 "건너뛰기" 버튼으로 여러 단계를 진행합니다. 한 번 본 사용자에게는 다시 보여 주지 않습니다.

## 사용하면 좋은 경우

- 업데이트로 추가된 **새 기능**이나 위치가 바뀐 메뉴를 알려 줄 때
- 제스처나 아이콘처럼 화면만 봐서는 **발견하기 어려운** 기능을 소개할 때
- 처음 실행할 때 핵심 동작 두세 가지만 짧게 짚어 주고 싶을 때

## 사용하지 말아야 할 경우

- 단계가 **너무 많을 때**. 3단계를 넘기면 대부분 건너뜁니다. 꼭 필요한 것만 남깁니다.
- 화면 설계가 어려운 것을 안내로 **덮으려 할 때**. 먼저 라벨과 배치를 고치는 것이 낫습니다.
- 사용자가 무언가를 하려는 도중에 **갑자기 띄울 때**. 작업 흐름을 끊지 않는 시점(화면 진입 직후, 빈 화면 등)에 보여 줍니다.
- 건너뛰기 수단 없이 끝까지 보도록 강제할 때

## 플랫폼별 차이

| 항목 | Material Design 3 | iOS HIG |
|---|---|---|
| 공식 명칭 | 해당 컴포넌트 없음 (Material 2에는 Feature discovery 패턴이 있었음) | 해당 컴포넌트 없음 |
| 가까운 대안 | Rich tooltip, 빈 화면 안내 | TipKit의 inline tip, popover tip (iOS 17 이상) |
| 표시 방식 | 앱이 직접 구현 (스크림 + 하이라이트 + 말풍선) | TipKit은 스크림 없이 대상 옆에 팁을 띄우고, 표시 횟수·조건 규칙을 지원 |
| 다시 보지 않기 | 앱이 직접 기록 | TipKit이 팁별로 표시 여부를 기억 |

두 플랫폼 모두 공식 Coach Mark 컴포넌트는 없습니다. 많은 앱이 직접 구현하는 패턴입니다. iOS에서 새로 만든다면 화면 전체를 덮는 방식보다 **TipKit**처럼 대상 옆에 가볍게 띄우는 팁이 플랫폼 관례에 더 가깝습니다.

**접근성 주의:** 스크림으로 화면을 덮는다면 모달과 같게 다뤄야 합니다. 포커스를 말풍선 안에 가두고, Esc나 "건너뛰기"로 바로 끝낼 수 있게 합니다. 하이라이트 위치만으로 대상을 가리키므로, 말풍선 글에도 어떤 요소인지 이름을 적어 줍니다.
