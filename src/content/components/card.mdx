## 정의

Card는 **한 가지 대상**(상품, 장소, 글 등)에 관한 정보를 하나의 표면에 모아 담는 컨테이너입니다. 여러 장을 목록이나 격자로 늘어놓으면, 사용자는 카드 단위로 훑어보고 고를 수 있습니다.

Material Design 3는 표면을 구분하는 방식에 따라 세 가지를 정의합니다.

- **Elevated card**: 그림자로 배경에서 떠 보입니다.
- **Filled card**: 진한 배경색으로 구분합니다.
- **Outlined card**: 테두리로 경계를 표시합니다.

카드 전체를 눌러 상세 화면으로 이동하는 경우가 많습니다. 이때 카드 안의 작은 버튼(저장, 더보기)은 카드 이동과 **따로** 동작해야 합니다.

## 사용하면 좋은 경우

- 이미지·제목·설명처럼 **종류가 다른 정보**를 한 대상 단위로 묶어 보여 줄 때
- 상품, 장소, 기사처럼 **비교하며 훑어보는** 목록일 때
- 대상마다 크기나 내용 구성이 조금씩 달라서 단순한 목록 행으로는 담기 어려울 때

## 사용하지 말아야 할 경우

- 이름 한 줄처럼 **정보가 단순한** 항목일 때. 일반 목록 행이 더 빽빽하고 빠르게 읽힙니다.
- 카드 안에 카드를 **겹쳐** 넣을 때. 경계가 겹쳐 구조가 흐려집니다.
- 카드 안에 동작 버튼을 여러 개 넣어 **어디를 눌러야 할지** 모호하게 만들 때
- 화면 전체 레이아웃을 카드로만 나눠 모든 것이 같은 무게로 보이게 할 때

## 플랫폼별 차이

| 항목 | Material Design 3 | iOS HIG |
|---|---|---|
| 공식 명칭 | Card (elevated, filled, outlined) | 해당 컴포넌트 없음 |
| 가까운 대안 | (해당 없음) | 둥근 모서리 그룹 목록(inset grouped list), 컬렉션 뷰 셀, 위젯 |
| 모서리 | 12dp | 앱마다 다름 (시스템 목록은 약 10pt) |
| 구분 방식 | 그림자, 배경색, 테두리 중 하나 | 주로 배경색 차이로 구분하고 그림자는 적게 씀 |

iOS HIG에는 Card라는 컴포넌트가 없습니다. 비슷한 묶음은 둥근 모서리의 그룹 목록이나 컬렉션 뷰로 만듭니다. App Store의 "투데이" 카드처럼 앱이 직접 디자인한 카드도 흔합니다.

**구현 주의:** 카드 전체를 `<button>`이나 `<a>`로 감싸면 안에 있는 다른 버튼이 "버튼 안의 버튼"이 되어 HTML 구조가 잘못되고, 스크린 리더가 카드 전체 글을 버튼 이름으로 읽습니다. 데모처럼 **제목 링크의 클릭 영역만 카드 전체로 늘리고**, 안쪽 버튼은 그 위에 올리는 방식을 씁니다.
